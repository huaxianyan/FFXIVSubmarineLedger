# 工程细则

`AGENTS.md` 只留约定与边界，这份放技术细节。改识别、界面、数据或测试前先读对应小节。

## 识别路线与语言

- 语言分开做，**日语优先**。每语言一个 `IChatLogParser` 实现加一份物名表，新增语言不动 UI、存储与统计。
- `ITextSource`（截图 + OCR / 剪贴板 / 后续游戏内直读）与 `IChatLogParser` 必须分开，因为初版之后要做「直接读游戏文本」。
- 物名是封闭小集合，识别只需在词表内找最像的一条；OCR 不必完美，靠词表纠错与人工确认兜底。
- 日文行格式（真实样本核实）：`[HH:MM] 角色名は ▶ 物名×Nを入手した。`，HQ 物品在物名与 `×N` 之间多一个 `◉`。数量与物名同行、无空格分隔。
- **聊天框直读的真实格式**（内存读取实测）：没有 `▶` 标记，`×` 更接近半角；另有「〜の景品として、…を入手しました。」这类无主语行，因此解析必须要求 `<角色名>は` 分隔符。
- Sharlayan 使用要点：`ChatLogFirstRunReadsBacklog = true` 才能拿到缓冲历史；连上后不要额外 `GetChatLog()` 预热（会白白消耗缓冲，第一版就栽在这里读到 0 行）；首次读取需轮询（约 500 ms 内才就绪）。
- **HQ 在聊天框里是物名后缀 `[HQ]`**（截图渲染才是 `◉`）。不认它会连带出三个症状：物名带后缀匹配不上词表、单价归零、行默认不勾选，界面看着像「什么都没读到」。2026-10-27 实测踩过。
- 掉落表 44 条，按沉船航线的掉落并集收：8 件沉船首饰、宝石与矿石（聊天框直读才会见到）、海産油脂、インゴット 等。词表漏一条就会显示「未命中」。
- **读取器每次调用都返回整段累计历史**（实测同进程连读两次行数相同），调用方必须去重。键是「艇名 + 原始行」，不是「同一句话出现过几次」。
- 聊天缓冲是**固定 1000 条环形表**，首读带回缓冲历史，因此「先收完艇再开程序」能补读，除非被 1000 条新聊天挤掉。
- 自动监听写成同步命令 + 后台循环：`async` 命令执行期间按钮会被禁用，「停止监听」会点不动。

## OCR 与预处理

- 日志窗口没有底板，文字压在 3D 场景上，实测背景亮度跨 8–180：**必须按行带自适应二值化，不得用全局阈值**。
- **OCR 是 Tesseract 5 + 随包分发的 `tessdata_fast` 日文模型**（`src/FFXIVSubmarineLedger.Desktop/Data/tessdata/jpn.traineddata`，2.4 MB）。不得改成依赖系统语言包的方案（`Windows.Media.Ocr` 就是因此被否的）。`tessdata_best` 是备选升级旋钮，14 MB、耗时翻倍、词间插空格，只在当前模型确实不够时才换。
- **行定位的抗亮背景规则（2026-11-22 加）**：行投影数的是「亮度 ≥ 200 且上下 2 px 内有深色描边」的像素——日志字是白字带黑描边，成片的亮背景（地板、招牌）周围没深色。整块日志压在亮色场景上时，裸亮度会把相邻几行粘成一条 89 px 高带子，再被行高上限整块丢掉（实测因此丢了整行收益）。所以**过高的带子不直接丢**：在带内按描边重新分带，切出来的行左右边界也按描边收紧（否则亮背景块被裁进去，Otsu 阈值被拉偏，整行读成乱码）。正常高度的带子照旧按裸亮度定左右边界——全部改成描边会把裁剪边界挪动几个像素，Tesseract 跟着翻字，老样本（756 × 798）上已实测变差。
- 预处理：裁行带留 2 px → 双线性放大 3 倍 → **每行单独 Otsu** → 反相成白底黑字。判文字用严格大于阈值，用 `>=` 会把背景算成文字、整行变黑。
- 已知固定误读：`▶`→`5`/`5p`/`pg`/`p`，`×`→`X`/`※`/`メ`/`ぶ` 或直接吞掉，`◉`→`6ぐ`/`で`，`潜水艦`→`替水艦`/`深水艦`。这些字符不在物名里，先剥噪声再匹配词表。
- 实测（756 × 798 样本、26 行）：26/26 行读出内容，入手行物名 14/14、数量 14/14 正确，合计 779,378 vs 真值 779,434（差 56，全是两条被吞掉 HQ 标记的エメラルド）。
- 实测（1197 × 877 样本、26 行文本，日志下半压在亮色地板上）：收益行 16/16 入账，物名 16/16、数量 16/16、HQ 6/6 正确，合计 227,110，与按真值逐行手算一致。修之前是 15 行（最后一行被粘成高带子整块丢掉）、3 行未命中词表、3 行未标明艇。

## 解析与匹配

- 行模板不认固定符号，只认结构：以「を入手」结尾、末尾是数字、数字前是噪声字符（`×`/`X`/`※`/`メ`/`ぶ` 等）、再前面是「は」加链接标记。实现在 `Infrastructure/Parsing/JapaneseLogLineParser.cs`。
- **链接标记不逐一列举**：日文物名一律以假名或汉字起头，所以「角色名は」之后直接跳到第一个假名/汉字（`▶` 被读成 `5`/`5p`/`pg` 这类随机串，列举追不上）。整串都被削空时保留原样，让它以「未命中」露出来，不能当成解析失败悄悄丢掉。
- **潜艇行只认「水艦「」+「」の探索完了」**：日志底部那几行压在亮色场景上、带半透明，OCR 常把第一个字读错（实测 `替`、`深`），而「水艦「…」の探索完了」这个组合在日志里只属于这一行，少认一个字不影响唯一性。
- 词表匹配用编辑距离，上限 `min(2, 物名长度/4)`；距离相同时按卖店价降序，默认取贵的。实现在 `ItemMatcher`。
- **歧义必须显式标出，不能静默取第一个**。真实案例：OCR 把「高級首飾り」读成「高級括飾り」，到「首飾り」与「耳飾り」距离都是 1。
- **HQ 不可靠**：`◉` 经常被 OCR 吞掉，而 HQ 直接影响单价。确认界面必须提供可切换的 HQ 开关，不能只靠识别；物名不能 HQ 时开关置灰。
- 确认界面每行可取消勾选（不入账）、改数量、切 HQ、在歧义时选候选、给词表外物名手填单价、改艇归属。合计实时重算。艇归属下拉里是**角色名下所有艇 + 未标明**，不是只列本批出现过的——艇名读歪或两艘串在一起时，得能改回去。
- **层级是 角色 → 艇 → 记录**（2026-10-27 加的）。归属凭据是聊天框里的「潜水艦「X」の探索完了」行，它出现在收益行**之后**，所以要先攒入手行、遇「探索完了」再整批结算给那艘艇。一次读取里有几艘艇就写几笔记录。没等到归属的行 `SubmarineName` 留空，统计里是「未标明艇」。
- **归属必须在整段有序聊天缓冲上算**，不能只拿「本轮新增的行」去解析——那样常常拿不到后面那行「探索完了」，归属会算错（实测把 Cranberry 的一笔记成了 Blackberry）。正确流程：整段扫描 → 完整条目表 → 用「艇名 + 原始行」作键去重 → 只落新条目；未等到「探索完了」的条目不结算。同名道具分属两艘艇时不能被并成一条。确认界面每行有艇归属下拉，人可纠正。
- **艇名要先对回已有的艇，再落库**（2026-11-23 加）：OCR 把艇名读歪一个字就会凭空造出一艘艇。实测一次截图把 Blackberry 读成 Blackberrvy、Blueberry 读成 Blug5erry、Strawberry 读成 Strawberrv，一落库就多了三艘各一条记录的艇，按艇统计从此对不上。做法是 `Application/Records/SubmarineNameMatcher` 的两档阈值（都按名字长度缩）：唯一一艘落在「可以直接改写」那一档才改写；落在只宽一档的「给候选」范围里的一律改成未标明并把人叫过来选，既不猜也不新建；两档都不沾的才当新艇。8 字以下的艇名不自动改写——「Sub1」「Sub2」这种编号命名差一个字就是另一艘。识别完与落库前各刷一次角色名下的艇名，界面上的解析过期也不会造艇。
- **角色按行归属，没有默认角色**（2026-11-28 改，之前是「默认角色/没默认取第一个」）。`JapaneseLogLineParser.TryTakeActorPrefix` 拆出「<角色名>は」里的角色名（`ActorNameLimit = 40`，顺带削掉敬称「さん」），`RecognizedLoot.CharacterName` 带着它一路走到确认行。`OwnershipResolver` 把读到的角色名对回已登记的角色，落库时按「**角色 + 艇**」分组，一个组合一笔记录——多角色同一天收艇各记各的。
- **对不上就停下，不猜也不新建**：`NameMatcher` 两档阈值（唯一一个落在 `AutoDistance = 2` 内才自动改写；再宽一档只给候选），角色名读歪一个字（`Tilna` → `Tiina`）会改写并标出来，像但不是唯一/没登记过/同名不同服的都置空等人在行内选。有任一行没选角色就不许入账（`CanSave`），因为静默算到别人头上比不入账更糟。
- **比对前抹空格、统一小写**（`NameMatcher.NormalizeKey`）：整行在解析入口就削了空白（OCR 常在字间插空），角色名会变成 `TiinaBranford`；玩家手填也不会照抄游戏里的写法，`tiina branford` / `TIINA BRANFORD` 都很正常。按大小写敏感去比，前者只是「读歪一个字」要反复提示，后者会被当成没见过的名字——整批收益认不出角色，艇还会被当成新的再建一艘。角色页查重（角色名、艇名）用同一个口径，`RosterEditor` 不会让 `Blackberry` 和 `blackberry` 同时存在。
- 合并键是「`ItemId` + 品质」，词表外物名用物名当键（否则不同未知物因 `ItemId` 都是 0 会被并成一条）。数量为 0 的行丢弃。
- 写完清场（清图、清行）。记录可在统计页看与删。
- 识别结果必须人工确认后才落库。

## 计价

- 潜艇产出全部卖店，不查市场价、不联网取价、无价格缓存。
- 卖店价 = XIVAPI v2 `Item` 表的 `PriceLow`（不是 `PriceMid`，那是 NPC 售价）。日文名按 `language=ja` 取。
- **HQ 卖店价 = `ceil(NQ × 1.1)`**，整数写法 `(nq * 11 + 9) / 10`。价格表只存 NQ 价，HQ 现算。取整方向已用五个道具的 NQ/HQ 双价验证过（见 `PLAN.md` 6.5.1），不是四舍五入。
- `CanBeHq` 为假的物名，OCR 若读出 `◉` 一律按误识处理，价格按 NQ。

## 金额显示

- **金额用 long，不用 int**：每天四艇约 360 万 Gil、一年 3.6 亿，int 上限 21.4 亿，六年左右溢出（统计页抛 OverflowException，已用 30 亿数据复现过）。
- **主显示是概数「141.8 万 Gil」（最多一位小数，截断），副行小字才是精确值**，别反过来。
- 门槛满一亿才换「亿」，整数截断所以不会出现「10000 万」。换单位门槛正好一亿（没满仍是「万」），小数位截断不四舍五入，否则 9999.99 万会变成「10000 万」。
- 已铺到四张卡、三种占比行、记录行、趋势纵轴、记账页汇总。容量上一年约 1.2 MB、十年约 11 MB。

## 界面与交互

- 界面框架沿用同作者的 FFXIVConfigManager：`App.axaml` 只放 `FluentTheme` 与 `ViewLocator`，样式写在视图内；左侧 220 px 侧栏 + 「页头/内容/底部说明」；叠加色 `#0A808080` / `#40808080` / `#0E808080`。
- **明细在「收艇记录」页，不在统计页**。**角色/艇筛选固定在标题栏**（`MainWindow` 那块，绑 `ActiveFilter`），收艇记录页与收益统计页各持一份 `RecordFilter`，样式一致、互不影响。别再往正文里塞筛选块。`ShellLayoutTests` 会断言筛选在标题栏、其他页没有筛选、导航顺序是「收艇记账 → 收益统计 → 收艇记录 → 角色管理 → 设置」（统计在明细之上）。
- **两页各自加载数据**：`LedgerPageViewModel` 与 `StatisticsPageViewModel` 都从仓储自己读，不共享筛选结果——用户要求筛选互不牵连。
- **收艇记录页每行的排版**：左起日期 → 两行块（上行艇名加粗、下行「角色 @ 服务器」）→ 物品明细 → 右端金额两行 → 删除按钮。角色行必须放得下完整名字，别用固定窄列（`LedgerLayoutTests` 会量宽度断言）。
- **改界面别靠开窗口截图**（会打断用户）：①`dotnet test --filter XamlGridColumnTests` 静态检查 `Grid.Column`/`Grid.Row` 是否超出 Grid 的列数——写错列号 Avalonia 不报错、控件会压到别的东西上（「已入账记录」的金额压到删除按钮就是这么来的）；②`PROBE_OUT=<png> dotnet test --filter RenderProbe` 用 headless + Skia 把统计页渲染成 PNG 自己看。
- **窗口位置**：`MainWindow.EnsureOnScreen()` 会把跑到屏幕外的窗口拉回主屏中央（拔显示器、改分辨率或缩放后可能发生）。
- **界面品牌**：侧栏写英文产品名 `FFXIV Submarine Ledger` + 一行本地化副标题（中文「潜艇收益统计」/ 日文「潜水艦収益集計」）；窗口标题也是这个英文名。

## 启动、诊断与外部干扰

- **建表必须在组合根里、读设置之前**（2026-11-28 修）：界面语言在开窗前就要定下来，所以要读设置；而设置存在 `settings` 表里。建表如果排在组合根构造之后，全新安装必然在第一次启动就报 `no such table: settings`（v0.1.0–v0.1.2 三个版本都是这样，开发机上因为库早就建好了所以看不出来）。现在 `ApplicationComposition` 构造的第一件事就是 `database.Initialize()`，`App.axaml.cs` 里不再重复调。回归测试在 `Desktop.Tests/FreshInstallTests`：空目录能装配、同一目录能装配两次。
- **启动顺序、单实例与诊断**：窗口先建、先显示，再去开数据库（库里被占着时开库会等锁，那段时间若窗口还没建，用户看到的就是「进程在跑、界面不出来」）。有单实例互斥，第二个进程把已有窗口叫到前台后退出。启动路径每一步都写 `%LocalAppData%\FFXIVSubmarineLedger\logs\startup.log`（含 pid），致命错误弹系统消息框而不是静默退出，另有 20 秒看门狗。SQLite `DefaultTimeout=5`，库被锁时快点报错，不干等。
- **软件渲染开关**：`--software-render` 或环境变量 `FFXIVSUB_SOFTWARE_RENDER=1`。显卡驱动初始化挂住时用它绕过。
- **MacType 会弄死这个程序**：MacType 钩 GDI/DirectWrite，Avalonia 的字体与渲染初始化正好走那条路，被挂钩后卡死在平台初始化（`AppBuilder 已构建` 之后、`App.Initialize` 之前），表现是「进程在跑、窗口不出来」。**改 exe 名字后必须把新名字加进 MacType 的排除列表**——2026-10-28 从 FFXIVSubLedger.exe 改名成 FFXIVSubmarineLedger.exe 后，旧排除规则失效，用户就撞上了。排查时先看 `logs/startup.log` 停在哪一步，卡在 `AppBuilder 已构建 → App.Initialize` 之间基本就是这类外部字体/渲染钩子。
- **命名**：项目名、仓库、解决方案、程序集、可执行文件、数据目录全部是 `FFXIVSubmarineLedger`（早期叫 `FFXIVSubLedger`，2026-10-28 统一改名）。旧数据目录 `%LocalAppData%\FFXIVSubLedger` 在首次启动时整体搬到新目录，两个都在就都不动。
- **别在 artifacts/publish 里直接跑 exe**：那是打包中转目录，`tools/publish.ps1` 每次都整个删掉重建，在里面运行会撞上文件被替换。给人用的目录是解压出来的 `artifacts/run`（或 zip 解压到任意位置）。

## 数据库与备份

- 数据库在 `%LocalAppData%\FFXIVSubmarineLedger\subledger.db`。
- 老库升级：`Initialize()` 会用 `pragma_table_info` 检查缺列并 `ALTER TABLE ADD COLUMN`，不要求用户重建库。备份格式已升到 `Version` 2（含艇），导入只认当前版本。
- **备份（设置页）**：导出是明文本 JSON（当前 `Version` 2 = 导出时间 + 角色 + 部队 + 艇 + 记录 + 明细）；导入是**整体替换**，单事务删空再写入，导入前自动存 `<数据目录>/backups/before-import-<时间>.json`。版本不认识就拒绝，不猜迁。设置表暂不在备份里（补时要升版本号）。
- 统计口径在 `Application/Records/LootStatistics`：日均 = 总收益 ÷ 自然日跨度（含首尾），不剔除无记录日；月均/年均按日历月与日历年数；另有按道具与按角色的占比。趋势图（`Desktop/Controls/TrendChart`）是自绘的，不引图表库，空档补 0，日/月可切。CSV 导出带 UTF-8 BOM（不带则 Excel 读中日文乱码）。

## 角色管理与艇改名

- **角色卡一屏看完**：角色名、服务器、名下每艘艇的名字**横排**成小胶囊，摆在同一张卡里。缺省不写「还没有潜水艇」这类空话，没有艇就什么都不显示——中文界面也不用「潜水艦」这个日文词（2026-11-28 用户指出）。
- **新建时就能填艇名**：添加区固定 4 个位置（游戏上限 4 艘），占位写「艇名 N（可留空）」。空着的跳过，填了就在建角色的同时把这艘登记下来——不用等第一次收艇才让名字从日志里冒出来。
- **编辑态固定 4 个位置**：已有的艇按顺序占前几个（带当前名字），剩下补空位。新角色一艘都没有时就是 4 个空白框。空位填了名字保存时新建，空位继续空着就跳过。
- **点「编辑」整张卡一起改**：角色名、服务器、每艘艇的名字同时变成输入框，保存时走 `RosterEditor.SaveAsync` **一次性校验、一次性写入**。分两次存最容易存半张：改到第三艘撞名报错时，前两艘已经写进去了，剩下那艘没人管。所以先把所有名字检查完，再动第一个字节：
  - 角色名非空、同名同服不重复（否则归属解析会「分不清是哪一位」）；
  - **卡内艇名互不重复**（两艘同名艇会让之后的归属再也分不清），空位不算错；
  - **已有艇被清空名字要报错**，不当成「不改」悄悄放过；
  - 艇必须确实属于这个角色（列表放旧了也不能拿别的角色的艇来改名）。
- **艇名横排没有标签**：位置就在角色下面，靠上下文认，不额外写词。
- **改名改的是同一行，ID 不变**：历史记录还挂在同一艘艇上；游戏里改过名之后在这里同步一次，之后日志里出现新名字还是同一艘，不会分裂成两艘新艇。
- 角色页**只有 Ctrl+V 没有粘贴按钮**（用户要求）：添加区那两个输入框里接管并拆「名字@服务器」，改角色名/艇名的输入框里放过让 TextBox 自己粘。

## 更新检查

- 只打 `api.github.com/.../releases/latest` 查版本号，不下载不安装。仓库没发过正式版时 GitHub 回 404，按「已是最新」处理（别当成错误弹给用户）。失败分 网络 / HTTP / 响应读不懂 三类，各给一句人话。
- 代理三种模式（系统/不用/自定义），只用于更新检查；记账全程不联网。**自定义代理是分开填协议、地址、端口的**（不要退回让用户写 URL）：协议只有 http/socks4/socks4a/socks5——`SocketsHttpHandler` 不认 `https://`，写了要到发请求时才炸；换协议自动补默认端口（HTTP 8080、SOCKS 1080）；误填按类型分别提示。旧版存的一整串 `ProxyUrl` 在读设置时自动拆分（`MigrateLegacyProxyUrl`），别删。

## 调试模式

- 设置页开关打开后把从聊天框读到的原文追加到 `<数据目录>\chatlog\chatlog-<时间>.txt`，给其它语言客户端留适配入口（解析器只认日文行结构，换语言得先拿真实样本）。

## 图标流水线

- **图标是用户给的金色浮雕潜艇纪念币**，源图 `tools/icon-source.png`（1254×1254、纯黑背景），由 `tools/make_icon.py` 抠底 + 重采样打包，别手改 `.ico`。自制矢量版（金币浮雕潜艇）在提交 `165650a`，要换回来从那里取。
- 七条不能省的：①**按连通区域抠底，不套圆形遮罩**——这枚币边缘各角度半径 472–490，套遮罩要么切一块要么留黑边，做法是从四边出发把「暗且连通到边界」的像素标成背景，币面凹陷再暗也留着；②**重采样走预乘 alpha**，否则透明处的黑渗进边缘成脏边；③**面积平均不用双线性**——1254→16 是 78 倍缩小，双线性只采 4 个点，细节全丢还起锯齿；④**币缘必须修成正圆**——源图边缘各角度半径 471–492 摆动，缩到 19 px 是一圈毛刺；取平均半径做正圆，圆内原透明处用同方向「边界往里 2 px」的暗边色补（取最小半径做遮罩也能圆，但削掉 3.5% 直径且各角度颜色不一致）；⑤**按尺寸补对比**——源图浮雕是细纹理，高通标准差仅 27/255，16 px 不补亮度标准差只有 25、补到 34；⑥**压高光**——币缘有接近纯白的高光 `#FEFDE2`，缩到 19 px 成白斑；⑦**先拉对比再压高光**，顺序反了等于白压（对比度会把 0.87 拉回 255）。
- 另有：先裁到包围盒再居中、边距按像素算（不裁会偏小且不居中，16 px 看得出来）；`--sheet` 出对照图、`--preview` 打 ASCII 预览。`ShellLayoutTests.WindowIconLoads` 守着窗口图标能加载（路径写错 Avalonia 建窗口就抛异常，表现成「双击没反应」）。

## 多语言

- 语言资源在 `src/FFXIVSubmarineLedger.Application/Localization/language-*.json`，嵌入式资源，每个文件自带 `language.tag` / `language.name`。加语言只加文件，设置页下拉由 `Loc.Available` 生成，键集合有测试守着。
- **文件名不能带点号分段的语言名**（`strings.ja.json`）：MSBuild 会当成附属程序集的文化，只生成卫星程序集，主程序里读不到（踩过一次，排查了半天）。
- 道具名在 `Data/items.json` 的 `names` 键值里按 ItemId 绑定，落库只存规范名，显示按 ItemId 换语言。金额单位写 `Gil`。
- Avalonia 12 的绑定引擎**不认索引器通知**（`PropertyChanged("Item[]")`，连属性名为空的全量通知也不行），所以文案不能绑索引器路径，必须绑普通属性——这个坑用无头测试 `LocalizationBindingTests` 钉住了（`tests/FFXIVSubmarineLedger.Desktop.Tests`，xunit v3 + Avalonia.Headless）。
- 换语言时 XAML 文案靠 `LocalizedText`（每处一个，普通属性通知）刷新；**代码拼出来的文字**（角色行徽标、筛选下拉「全部角色」、确认行「未标明艇」、状态行、掉落表那行）必须各自实现 `Relocalize()`，由 `MainWindowViewModel` 统一调用——漏了就是「切到日语还有中文」。
- **切语言的测试要串行**：`Loc` 是进程级单例，xUnit 默认并行跑测试类，两个类同时改语言会互相踩、断言随机失败（踩过）。会改语言的测试类都挂 `[Collection(LocalizationCollection.Name)]`，该集合 `DisableParallelization = true`。

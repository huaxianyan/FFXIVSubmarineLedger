这版只修一个启动问题：全新安装第一次打开会弹「no such table: settings」，然后程序退出。已经装过旧版、库早就建好的用户不会遇到。

## 问题修复

- **全新安装起不来**：程序把窗口显示出来之后要先读设置（界面语言在开窗前就得定），而设置存在数据库的表里；建表却排在读设置之后，空库上必然查不到表，于是抛 `SQLite Error 1: 'no such table: settings'` 并退出。从 v0.1.0 起的三个版本都有这个问题，开发机上因为库早就在了，一直没露出来。
- 现在装配数据层的第一步就是建表（`CREATE TABLE IF NOT EXISTS`，幂等），全新安装与老库升级走同一条路；启动流程里原来那句重复的建表调用已去掉。
- 加了两条回归测试：空数据目录能装配出一套可用的数据层，同一个目录能装配第二次（幂等）。

之前启动失败的用户，`%LocalAppData%\FFXIVSubmarineLedger\` 下那个空库会被自动建表，装完直接可用，不需要手动删。已经能正常用的旧版本，覆盖安装后数据不受影响。

完整实现与验收记录见 [工程细则](https://github.com/huaxianyan/FFXIVSubmarineLedger/blob/v0.1.3/docs/ENGINEERING.md)。

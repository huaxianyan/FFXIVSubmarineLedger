# 实机测试清单

发布版拿去真机验证时按这份走。每次改动后重新打包，记得把本文件一起复制过去。

## 一次性准备

1. 打开程序，先去设置页 **导出一次备份**——测试记账会写进正式库（`%LocalAppData%\FFXIVSubmarineLedger\subledger.db`）。
2. 确认游戏在运行并且角色已登录。

## 直读聊天框

1. 「收艇记账」页点 **自动监听**（按钮变「停止监听」，状态栏显示「正在监听聊天框…」）。
2. 回游戏收艇。
3. 收完看程序：
   - 状态栏应显示「监听中：本次读到 N 条入手行，已累计 M 行待核对」；
   - 下方「本次识别」卡片逐行列出，**每条带艇名**（如 `Strawberry`）；
   - 顶端有「记入账」按钮。
4. 核对三处：
   - **HQ**：`ルビー[HQ]` 应显示 `ルビー（HQ）`、单价 3（聊天框里 HQ 是 `[HQ]` 后缀，截图渲染才是 `◉`）；
   - **艇归属**：与游戏里「潜水艦「X」の探索完了」的顺序一致；每行下方有艇下拉，识别错了可以直接改；
   - **总额**：与游戏内实际卖店价相符。
5. 若出现「词表里没有」的行，填单价后才能写账（没填会被拦下并提示）。
6. 点「记入账」→ 去统计页：先选角色，再看艇下拉、按艇占比、趋势图。

## 截图识别（保底路径）

1. 截一张收艇日志窗口的图，拖进页面或 `Ctrl + V`。
2. 预览上应画出每行的行框；「显示行框」可切换。
3. 同样的核对与写账流程。

## 出问题怎么看

状态栏那句话直接指出断在哪一步：

| 状态栏 | 含义 |
| --- | --- |
| 没读到聊天内容 | 读取器没拿到东西：游戏没运行、没登录，或权限与游戏不同级 |
| 读到 N 行聊天内容，但没有新的入手行 | 读到了，但里面没有入手行（可能被挤出 1000 条聊天缓冲） |
| 读到 N 行，认出 M 条 | 正常，去核对并写账 |
| 还有 N 行没填单价 | 词表外的物名，填了单价才能写账 |

要更细的诊断（只导出相关行，不含其它聊天内容）：

```powershell
.\FFXIVSubmarineLedger.exe --dump-chat-diag diag.txt
```

## 已知边界

- 聊天缓冲固定 1000 条，收完艇到开始读之间刷太多聊天可能把那几行挤掉，那就退回截图识别。
- 没等到「探索完了」行的收益标「未标明艇」。
- 艇的可选项取自该角色实际有记录的艇，第一次记完账统计页才有得选。

## 显示语言

设置页最上面是「显示语言」，切到 日本語 后逐页看一遍：按钮、表头、状态行、确认行的「潜水艦不明」
以及角色页的「既定／停止中／有効化」都应跟着变；切换不需要重启。

语言只影响显示，不影响收集：切到日语后照样能读日文日志。

## 不动窗口核对排版

改界面后不必开程序截图，两种方式都能自己看：

```bash
# 1) 静态检查：Grid.Column / Grid.Row 是否超出所在 Grid 的列数/行数
#    （写错列号时 Avalonia 不报错，控件会压到别的东西上）
dotnet test tests/FFXIVSubmarineLedger.Desktop.Tests --filter XamlGridColumnTests

# 2) 无头渲染：把统计页渲染成 PNG，不开窗口、不抢焦点
PROBE_OUT=/绝对路径/stats.png dotnet test tests/FFXIVSubmarineLedger.Desktop.Tests --filter RenderProbe
```

第 2 条用的是 Avalonia 的 headless 模式加 Skia 渲染，画面和真窗口一致，但不会出现在桌面上。
